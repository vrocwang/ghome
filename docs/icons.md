# 图标的解析与安全边界

[README](../README.md) 的「图标是怎么来的」只留结论。这里是被移出来的细节。

## 解析顺序（联网那一层）

1. 抓页面 HTML，解析 `<link rel="icon">`，也认 `shortcut icon` / `apple-touch-icon` /
   `mask-icon`。
2. 跟随页面里的 `<base href>` 解析相对路径。
3. 有多个候选时取 `sizes` 最大的那个。
4. 没有 `<link>` 就退到 `<host>/favicon.ico`——不少站点对爬虫返回 403 却仍然提供这个文件，
   所以值得猜一次。
5. 校验返回的确实是图片：先看 `Content-Type`，可疑时用前 512 字节嗅探。不是图片就算失败。

失败结果也会进缓存（5 分钟），避免对一个挂掉的站点反复重试。

## 缓存

| | 值 |
| --- | --- |
| 条目上限 | 512 |
| 字节上限 | 8 MB（总共） |
| 单个体积上限 | 512 KB |
| 成功结果 | 24 小时 |
| 失败结果 | 5 分钟 |
| 存续 | 仅内存——重启后重新预热 |

两个上限都要满足。只限条数的话，512 × 512KB 最坏是 256 MB，而这是个空载十几 MB 的服务。

**缓存键是完整的页面 URL**，不是 host。因为 `/api/icon` 是按 host 查的、而每个 host
只取配置里第一个用它的链接，所以正常情况下一个 host 只会有一个键被用到；预热时会按 URL
逐个抓，同一个 host 上的多个链接会被各抓一遍（这是多余的流量，但只发生在配置加载时）。

## `/api/icon` 的安全边界

- **只服务当前配置里出现过的 host**，不是开放代理。别人拿不到 `h=` 任意值去驱使服务端抓取。
- 响应带 `Content-Security-Policy: default-src 'none'; sandbox`。第三方 SVG 是从我们自己的
  domain 发出去的，不加这个，直接打开图标 URL 就能执行脚本。
- **允许列表管的是每一跳**，不只是第一个 URL：页面 HTML 里声明的图标如果指向别的 host，
  会被拒绝；302 跳到别的 host 也会被拒绝。
  代价是**放在 CDN 上的图标不会被抓取**——这种情况用 `--icon-dir` 放一个本地文件。
- 浏览器侧：favicon 走这个代理，所以那条路径上不访问第三方。但配置里显式写的
  `icon:` / `logo:` 图片 URL 是浏览器直连的，所以 CSP 的 `img-src` 是
  `'self' data: http: https:`（`http:` 是给纯 HTTP 的内网部署留的）。
- 响应带 `Cache-Control: public, max-age=604800`，**没有 ETag / Last-Modified**，所以浏览器
  在 7 天内不会重新验证。换了 `--icon-dir` 里的文件需要硬刷新（配置 revision 变化会让 URL
  里的 `?v=` 变，也能自动失效）。
